================================================================================
  sound_mouth_motik_emotions — запуск mouth / motik, карусель эмоций, звук
  Формат: plain text (UTF-8). Пакет: sound_mouth_motik_emotions
================================================================================

1. ОБЩИЕ УСЛОВИЯ ПЕРЕД ЛЮБЫМИ КОМАНДАМИ
--------------------------------------------------------------------------------
  • Должен быть запущен ROS master:
      roscore
    (или bringup, если он уже поднимает roscore.)

  • В каждом новом терминале:
      source /opt/ros/noetic/setup.bash
      source ~/ros_ws/devel/setup.bash
    (путь к devel подставьте свой, если отличается.)

  • OLED 3D на I2C 0x3D: одновременно на шину не должны писать посторонние сервисы
    (конфликт с другим процессом на 0x3D).


2. КТО РИСУЕТ НА ЭКРАНЕ 0x3D (mouth ИЛИ motik)
--------------------------------------------------------------------------------
  Одновременно картинку на дисплей отдаёт только ОДНА логика:
    • "mouth"  → нода robot_mouth_talk_node (рот / осциллограмма при воспроизведении)
    • "motik"  → нода emotions_display_node (эмоции)

  Переключатель (после того как нужные ноды уже запущены):
    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'mouth'"
    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"

  Стартовое значение драйвера задаётся параметром (если задан в launch):
    /oled_3d/active_driver_default
    По умолчанию в коде нод — "mouth", если параметр не выставлен.

  I2C-адрес OLED для рта/motik (если «лицо» не на 0x3D — см. п. 2.1):
    аргумент bringup: oled_3d_i2c_address (61 = 0x3D, 60 = 0x3C), пишет /oled_3d/i2c_address.

  После mouth → motik: emotions_display_node принудительно ставит эмоцию neutral (не остаётся
  smoke/«сигарета» из памяти ноды до переключения на mouth). Таймер карусели при этом сдвигается,
  чтобы neutral не сменился мгновенно следующим кадром карусели.

2.1. НА «3D» ЭКРАНЕ SSID, IP, CPU (системная инфо) ВМЕСТО РТА
--------------------------------------------------------------------------------
  Эту картинку рисует systemd-сервис ainex_bringup: scripts/oled_display.py на адрес I2C 0x3C.
  Ноды robot_mouth_talk_node / emotions_display_node по умолчанию пишут на 0x3D. Если физически
  «лицевой» модуль сидит на шине как 0x3C, на нём и остаётся инфо, а рот уходит на другой чип.

  Что сделать:
    1) Проверка:  sudo i2cdetect -y 1   — какие адреса 3c / 3d видны.

    2) Перевести рот/motik на тот же адрес, где «лицо» (часто 60 = 0x3C):
         roslaunch ainex_bringup bringup.launch oled_3d_i2c_address:=60
       (или в своём launch задать /oled_3d/i2c_address до старта нод.)

    3) Убрать конкуренцию с oled_display на ОДНОМ чипе — один из вариантов:
         • Два OLED: перенести системную инфо на второй (обычно 0x3D). В unit-файле
           oled_display.service раскомментировать и применить:
             Environment=OLED_INFO_I2C_ADDRESS=0x3D
           затем: sudo systemctl daemon-reload && sudo systemctl restart oled_display.service
         • Один OLED только под рот:  sudo systemctl disable --now oled_display.service

  ВАЖНО:
    • Переключение mouth ↔ motik имеет смысл, когда ЗАПУЩЕНЫ ОБЕ ноды
      (полный display_3d.launch с launch_mouth:=true).
    • Если запущен только motik (launch_mouth:=false), после переключения на
      "mouth" на экране никто не рисует рот — экран может быть пустым.


3. ПОСЛЕДОВАТЕЛЬНОСТЬ ЗАПУСКА (РЕКОМЕНДУЕМЫЙ ПОРЯДОК)
--------------------------------------------------------------------------------
  Шаг A. Поднять roscore (если ещё нет).

  Шаг B. Запустить ноды дисплея/звука одним из вариантов из раздела 4.

  Шаг C. Дождаться в логах сообщений о старте нод (и при необходимости —
         init_pose/init_finish у робота, если ноды ждут подъёма).

  Шаг D. Если подняты ОБЕ ноды и нужен экран рта — убедиться, что активен mouth:
         rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'mouth'"

  Шаг E. Если нужны эмоции на экране — переключить на motik:
         rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"

  Шаг F. Звук — только при работающей robot_mouth_talk_node и обычно при
         active_driver=mouth (картинка рта на OLED). См. раздел 6.

  Пауза между шагами: обычно 1–3 секунды после старта launch, пока ноды
  зарегистрируются в ROS; отдельная команда "sleep" не обязательна.


4. ВАРИАНТЫ ЗАПУСКА (LAUNCH)
--------------------------------------------------------------------------------

  4.1. Полный режим: mouth + motik (переключение топиком)
  ------------------------------------------------------------
    roslaunch sound_mouth_motik_emotions display_3d.launch

    Параметры (примеры):
      output_device:=default          — ALSA для pygame (aplay -l)
      mouth_sync_hz:=30               — частота обновления рта
      default_emotion:=neutral        — эмоция по умолчанию у motik
      cycle_emotions_demo_sec:=0      — 0 = карусель выключена при старте
      launch_mouth:=true              — по умолчанию; рот запускается

    Условие: нужны и звук/рот, и эмоции на одном роботе с переключением.

  4.2. Только эмоции + карусель (рот НЕ запускается)
  ------------------------------------------------------------
    roslaunch sound_mouth_motik_emotions display_3d.launch \
      launch_mouth:=false cycle_emotions_demo_sec:=2.5

    Или короткий алиас:
    roslaunch sound_mouth_motik_emotions emotions_motik_only.launch \
      cycle_emotions_demo_sec:=2.5

    При launch_mouth:=false в launch выставляется:
      /oled_3d/active_driver_default = motik
    Экран сразу у эмоций; карусель крутится каждые 2.5 с (или ваш интервал).

    Условие: проверка эмоций без звука и без ноды рта.

  4.3. Обе ноды, но карусель сразу включена
  ------------------------------------------------------------
    roslaunch sound_mouth_motik_emotions display_3d.launch \
      cycle_emotions_demo_sec:=2.5

    На OLED карусель будет видна только когда active_driver=motik:
    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"


5. КРУГ (КАРУСЕЛЬ) ЭМОЦИЙ
--------------------------------------------------------------------------------
  Порядок на дисплее: neutral → happy → sad → cute → smoke (по кругу).

  Включение при старте:
    параметр ноды emotions_display_node:
      ~cycle_emotions_demo_sec  > 0   (секунды между сменами)

  Включение / выключение БЕЗ перезапуска ноды:
    rostopic pub -1 /emotions_display/set_cycle_demo_sec std_msgs/Float32 "data: 2.5"
    rostopic pub -1 /emotions_display/set_cycle_demo_sec std_msgs/Float32 "data: 0.0"

  Один терминал: карусель крутится, пока не Ctrl+C (в этом же окне — стоп круга, публикация 0.0):
    # только интервал (motik должны включить сами, если нужен экран эмоций)
    rosrun sound_mouth_motik_emotions emotion_cycle_wait.py 2.5

    # с переключением на motik за вас
    rosrun sound_mouth_motik_emotions emotion_cycle_wait.py --motik 2.5

    rostopic pub -1 … завершается сразу — Ctrl+C в том же терминале потом не к чему привязать;
    для сессии «старт + стоп по Ctrl+C» используйте emotion_cycle_wait.py.

  Условия:
    • Карусель крутится только если active_driver == motik. (перешли на motik)
    • data > 0  — включить карусель с интервалом data секунд (с начала списка).
    • data <= 0 — выключить карусель; на экране сразу neutral; дальше эмоции
                  задаются вручную топиком /emotions.

  Остановка "круга" = публикация 0.0 на set_cycle_demo_sec (см. выше) или Ctrl+C в процессе
  emotion_cycle_wait.py. Это не останавливает ноду и не убивает roslaunch.

  Если emotions_display_node в TTY (rosrun): первый Ctrl+C — выключить карусель в ноде; второй
  за ~2 с — выход из ноды. Под roslaunch без TTY удобнее гасить круг через emotion_cycle_wait.py
  (Ctrl+C там) или rostopic pub … 0.0.


6. ВОСПРОИЗВЕДЕНИЕ ЗВУКА И ОТМЕНА (СТОП)
--------------------------------------------------------------------------------
  Условия:
    • Должна быть запущена robot_mouth_talk_node (не режим launch_mouth:=false).
    • Файл: в пакете папка voice/ или полный путь.

  Старт воспроизведения:
    rosservice call /oled_mouth/play_audio "data: 'имя_файла.mp3'"

    rosservice call /oled_mouth/play_audio "data: 'stop'"

  Ожидание до конца трека в одном процессе (РЕКОМЕНДУЕТСЯ: Ctrl+C → стоп в этом же терминале):
    rosrun sound_mouth_motik_emotions play_audio_wait.py имя_файла.mp3
    (внутри вызывается play_audio с суффиксом ::block; Ctrl+C шлёт /oled_mouth/stop_audio.)

  Альтернатива без Python (оболочка: Ctrl+C → stop_audio + прерывание клиента rosservice):
    rosrun sound_mouth_motik_emotions oled_play_block.bash имя_файла.mp3
    (без символа одинарной кавычки в имени; для сложных имён — play_audio_wait.py.)

  Режим ::block через сырой rosservice (ответ после окончания звука или стопа):
    rosservice call /oled_mouth/play_audio "data: 'имя_файла.mp3::block'"
  ВАЖНО: во время такого вызова клиент rosservice часто «зависает» на сокете и Ctrl+C
  может не сработать до конца трека. Для прерывания из этого же окна используйте
  play_audio_wait.py или oled_play_block.bash; иначе стоп из другого терминала:
  rosservice … "data: 'stop'" или rostopic pub … /oled_mouth/stop_audio.


  То же из любого терминала (удобно, если звук запускали rosservice call из другого окна):
    rostopic pub -1 /oled_mouth/stop_audio std_msgs/Empty

  Ctrl+C (SIGINT) и нода robot_mouth_talk_node: первый сигнал — то же, что stop (очередь + текущий
  трек); второй в течение ~2 с — выход из ноды. Работает и при запуске через roslaunch: нажимайте
  Ctrl+C в том же терминале, где запущен roslaunch (сигнал доходит до дочернего процесса ноды).
  Отдельный rosrun для рта не нужен.

  Важно: Ctrl+C в окне с обычным (неблокирующим) rosservice call — стоп ноде не уходит;
  для стопа: rosservice … "data: 'stop'" или rostopic pub … /oled_mouth/stop_audio.
  Для rosservice … "::block" см. предупреждение выше (лучше play_audio_wait / oled_play_block).

  Пауза: отдельной команды "пауза" в сервисе нет — используйте stop.


7. РУЧНАЯ СМЕНА ЭМОЦИИ (без карусели или вместе с ней до отключения карусели)
--------------------------------------------------------------------------------
  Условие: active_driver=motik.

    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"
    rostopic pub -1 /emotions std_msgs/String "data: 'neutral'"
    rostopic pub -1 /emotions std_msgs/String "data: 'happy'"
    rostopic pub -1 /emotions std_msgs/String "data: 'sad'"
    rostopic pub -1 /emotions std_msgs/String "data: 'cute'"
    rostopic pub -1 /emotions std_msgs/String "data: 'smoke'"


7.1. БЕЗДЕЙСТВИЕ → ЭМОЦИЯ SMOKE (таймер в emotions_display_node)
--------------------------------------------------------------------------------
  ~idle_boot_grace_sec (по умолчанию 60 с): первые N секунд после завершения init emotions_display_node
  принудительный smoke от бездействия не включается (осциллограмма/рот не перехватываются). После
  этого действует обычный ~idle_timeout_sec. Задать 0 — без задержки после старта ноды.

  Если ~idle_smoke_enabled=true и ~idle_timeout_sec>0 (по умолчанию 60 с), при отсутствии
  действий и пока /oled_3d/mouth_playback_active=false, на OLED принудительно motik + smoke.

  «Действие» сбрасывает таймер; если был smoke от бездействия:
    • rostopic pub … /oled_3d/active__driver … 'mouth' или 'motik' — переключение на выбранный
      драйвер и стартовый экран (mouth → рот/осциллограмма, motik → neutral).
    • Пинг от рта без смены драйвера — возврат к драйверу до простоя (как раньше).
    • /emotions или /emotions_display/set_cycle_demo_sec — сразу выбранная эмоция или карусель,
      без принудительного neutral между smoke и командой.
    • play_audio /oled_mouth/audio_path: robot_mouth_talk_node сам шлёт active_driver=mouth,
      затем очередь и звук — одной командой выход из smoke и воспроизведение.

  Переключатель (тип сообщения именно std_msgs/String):
    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'mouth'"
    rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"

  События действия: /emotions, /emotions_display/set_cycle_demo_sec, смена
  /oled_3d/active__driver (вручную), очередь/стоп play_audio, /oled_mouth/audio_path,
  /oled_mouth/mode; во время воспроизведения файла mouth_playback_active=true — таймер
  smoke не срабатывает.

  Отключить поведение: ~idle_timeout_sec:=0 или ~idle_smoke_enabled:=false.


8. ОСТАНОВКА ROSLAUNCH (Ctrl+C) И ПОВЕДЕНИЕ ЭКРАНА
--------------------------------------------------------------------------------
  При завершении emotions_display_node, если активен motik, нода перед выходом
  отправляет на OLED кадр neutral (чтобы экран не оставался чёрным).

  Полная остановка нод — Ctrl+C в терминале roslaunch.


9. КРАТКАЯ ШПАРГАЛКА
--------------------------------------------------------------------------------
  roslaunch … display_3d.launch
  rostopic pub -1 /oled_3d/active__driver … 'mouth' | 'motik'
  rosservice call /oled_mouth/play_audio "data: 'файл.mp3'"
  rosservice call /oled_mouth/play_audio "data: 'stop'"
  rostopic pub -1 /emotions_display/set_cycle_demo_sec … Float32 "data: 0.0"
  rostopic pub -1 /emotions … 'neutral' | 'happy' | 'sad' | 'cute' | 'smoke'
