# Архитектура системы: 3D дисплей + звук + эмоции

## 1. Общая схема запуска робота

```
                    ВКЛЮЧЕНИЕ РОБОТА
                         │
                         ▼
              systemd: start_app_node.service
              (After: oled_display.service)
                         │
                         ▼
           roslaunch ainex_bringup bringup.launch
                         │
           ┌─────────────┼──────────────────────┐
           ▼             ▼                       ▼
      base.launch    display_3d.launch     другие ноды
           │         (sound_mouth_          (камера, джойстик,
           │          motik_emotions)        app, teleop...)
           │              │
     ┌─────┴─────┐        │ ЖДУТ параметр
     ▼           ▼        │ init_pose/init_finish=True
ainex_controller IMU      │
(init_pose.yaml           │
 → сервоприводы           │
 → робот ВСТАЁТ           │
 → set_param              │
   init_finish=True) ─────┘
                     ┌───┴───────────────┐
                     ▼                   ▼
               robot_mouth_       emotions_
               talk_node          display_node
               (mouth)            (motik)
```

## 2. Порядок запуска (СТРОГАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ)

1. **systemd** запускает `oled_display.service` (инфо на OLED 0x3C: IP, батарея)
2. **systemd** запускает `start_app_node.service` (после `oled_display`)
3. `bringup.launch` запускается — все ноды стартуют параллельно, НО:
   - `ainex_controller` **сразу** начинает поднимать робота (сервоприводы за 1 сек)
   - `ainex_controller` ставит параметр `init_pose/init_finish = True` после подъёма
   - `robot_mouth_talk_node` и `emotions_display_node` **ждут** параметр `init_pose/init_finish=True` перед началом работы
   - Таймаут ожидания: 30 сек (если контроллер не появился — запускаются без подтверждения)
4. Робот стоит → дисплей 3D стартует → режим `mouth` (по умолчанию)
5. Если нода дисплея упадёт — робот продолжит стоять (ноды полностью независимы)

## 3. Два дисплея

| Адрес I2C | Назначение | Процесс |
|-----------|------------|---------|
| **0x3C** | Информация: IP, CPU, батарея | `oled_display.py` (systemd) |
| **0x3D** | 3D дисплей: mouth ИЛИ motik | `robot_mouth_talk_node` / `emotions_display_node` |

Дисплей 0x3D может использоваться только одним процессом. Переключение через топик `/oled_3d/active__driver`.

### Ноды

| Нода | Назначение | Активна когда |
|------|------------|---------------|
| `robot_mouth_talk_node` | Осциллограмма + воспроизведение звука | `active_driver == "mouth"` |
| `emotions_display_node` | Эмоции (happy/sad/neutral) | `active_driver == "motik"` |

### Топики

| Топик | Тип | Направление | Описание |
|-------|-----|-------------|----------|
| `/oled_3d/active__driver` | String | → обе ноды | Переключатель: `"mouth"` или `"motik"` |
| `/oled_mouth/audio_path` | String | → mouth | Путь к файлу для воспроизведения |
| `/oled_mouth/mode` | String | → mouth | Режим: `"idle"` / `"oscillogram"` |
| `/audio/mouth_open_level` | Float32 | → mouth | Уровень открытия рта 0..1 |
| `/audio/playback_level` | Float32 | mouth → | Уровень воспроизведения 0..1 |
| `/emotions` | String | → motik | Эмоция: `"happy"` / `"sad"` / `"neutral"` |

### Сервисы

| Сервис | Тип | Описание |
|--------|-----|----------|
| `/oled_mouth/play_audio` | SetString | Воспроизвести файл или `"stop"` для остановки |

## 5. Взаимодействие с ainex_bringup

```
ainex_bringup/                       sound_mouth_motik_emotions/
├── launch/                          ├── launch/
│   ├── bringup.launch ──include──→  │   └── display_3d.launch
│   └── base.launch                  ├── scripts/
├── scripts/                         │   ├── robot_mouth_talk_node.py
│   ├── oled_display.py (0x3C)       │   └── emotions_display_node.py
│   └── start_app_node.sh            └── voice/
└── service/
    ├── start_app_node.service
    └── oled_display.service
```

Пакет `ainex_bringup` отвечает за:
- Автозапуск робота (systemd → bringup.launch)
- Кинематику (base.launch → ainex_controller)
- Информационный дисплей 0x3C (oled_display)

Пакет `sound_mouth_motik_emotions` отвечает за:
- 3D дисплей 0x3D (mouth + motik)
- Воспроизведение звука
- Хранение аудио файлов

## 6. Как робот встаёт (детально)

1. `ainex_controller.py` загружает `init_pose.yaml` (углы суставов в радианах)
2. Конвертирует углы в импульсы сервоприводов (`angle2pulse()`)
3. Вызывает `set_servos_position(1000, init_servo_data)` — все сервоприводы плавно встают за 1 секунду
4. Action-файлы в `/home/ubuntu/software/ainex_controller/ActionGroups/`:
   - `stand.d6a` — встать из произвольного положения
   - `lie_to_stand.d6a` — встать после падения лицом вниз
   - `recline_to_stand.d6a` — встать после падения на спину

## 7. Безопасность: дисплей не мешает подъёму робота

- Ноды дисплея **ждут параметр** `init_pose/init_finish=True` перед началом работы
- `ainex_controller` сначала поднимает робота, потом ставит параметр в `True`
- Дисплей НЕ может помешать подъёму — он ничего не делает пока робот не встал
- Если нода дисплея упадёт — робот продолжит стоять (ноды полностью независимы)
- Дисплей НЕ перезагружает и НЕ останавливает робота
- Таймаут 30 сек: если контроллер не появился — дисплей запустится без подтверждения
