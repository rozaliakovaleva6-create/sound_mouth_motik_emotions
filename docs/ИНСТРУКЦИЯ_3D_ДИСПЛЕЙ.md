# Инструкция: 3D дисплей (OLED 0x3D)

## 1. Что это

OLED-дисплей 128x64 на адресе I2C 0x3D. Два режима работы:

- **mouth** — осциллограмма (три вертикальные полоски, высота по громкости звука)
- **motik** — эмоции робота (happy, sad, neutral, cute, smoke)

## 2. Команды управления

### Переключение режима дисплея

```bash
# Включить mouth (осциллограмма + звук) — по умолчанию при включении
rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'mouth'"

# Включить motik (эмоции)
rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"
```

### Воспроизведение звука (режим mouth)

```bash
# Воспроизвести файл из папки voice/
rosservice call /oled_mouth/play_audio "data: 'adam-dragon-us_3475244.mp3'"

# Остановить воспроизведение
rosservice call /oled_mouth/play_audio "data: 'stop'"

# Воспроизвести по полному пути
rosservice call /oled_mouth/play_audio "data: '/путь/к/файлу.mp3'"
```

### Управление эмоциями (режим motik)

```bash
# Сначала переключить на motik
rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"

# Затем установить эмоцию
rostopic pub -1 /emotions std_msgs/String "data: 'happy'"
rostopic pub -1 /emotions std_msgs/String "data: 'sad'"
rostopic pub -1 /emotions std_msgs/String "data: 'neutral'"
rostopic pub -1 /emotions std_msgs/String "data: 'cute'"
rostopic pub -1 /emotions std_msgs/String "data: 'smoke'"
```

**Список эмоций в логе:** при старте `emotions_display_node` в консоль ROS выводится нумерованный список (порядок как в карусели).

**Карусель на дисплее (все эмоции по очереди):** параметр ноды `~cycle_emotions_demo_sec` — интервал в секундах между сменами; при `> 0` и `active_driver=motik` на OLED по кругу показываются `neutral → happy → sad → cute → smoke`.

**Выключить карусель без чёрного экрана** (сразу **neutral** на OLED, нода продолжает работать):
```bash
rostopic pub -1 /emotions_display/set_cycle_demo_sec std_msgs/Float32 "data: 0.0"
```

**Остановка `roslaunch` (Ctrl+C):** перед выходом нода рисует **neutral** на 0x3D (если активен `motik`), чтобы экран не оставался пустым.

**Почему при `display_3d.launch` стартует и mouth:** файл по задумке поднимает **обе** ноды (рот/звук + эмоции); переключение — топиком `/oled_3d/active__driver`. По умолчанию параметр `active_driver` часто **mouth**, поэтому карусель на OLED **не видна**, пока не выполните `rostopic pub ... 'motik'`.

**Только эмоции (без `robot_mouth_talk_node`):**
```bash
roslaunch sound_mouth_motik_emotions display_3d.launch launch_mouth:=false cycle_emotions_demo_sec:=2.5
# или короткий алиас:
roslaunch sound_mouth_motik_emotions emotions_motik_only.launch cycle_emotions_demo_sec:=2.5
```

**Обе ноды + карусель** (нужно вручную переключить дисплей на motik):
```bash
roslaunch sound_mouth_motik_emotions display_3d.launch cycle_emotions_demo_sec:=2.5
rostopic pub -1 /oled_3d/active__driver std_msgs/String "data: 'motik'"
```

## 3. Как изменять дисплей

### 3.1 Изменить анимацию рта (mouth)

Файл: `scripts/robot_mouth_talk_node.py`

Функция `draw_mouth_mode7(mouth_open)` рисует осциллограмму:
- Три вертикальные полоски шириной 18px
- Высота зависит от `mouth_open` (0.0 — закрыт, 1.0 — максимум)
- Случайная вариация ±9px при `mouth_open > 0.1`

Чтобы изменить:

```python
def draw_mouth_mode7(mouth_open):
    img = Image.new("1", (W, H), 0)
    draw = ImageDraw.Draw(img)
    cx, cy = 64, 42            # центр рисования
    h = max(6, int(42 * mouth_open) if mouth_open > 0.02 else 0)
    for i in range(3):          # 3 полоски
        th = max(6, h + (random.randint(-9, 9) if mouth_open > 0.1 else 0))
        left, top = cx - 45 + i * 36, cy - th // 2
        draw.rectangle((left, top, left + 18, top + th), fill=255)
    return img
```

**Параметры для настройки:**
- `cx, cy` — центр рисования (по умолчанию 64, 42)
- `3` в `range(3)` — количество полосок
- `18` — ширина полоски
- `36` — расстояние между полосками
- `42 * mouth_open` — максимальная высота
- `random.randint(-9, 9)` — амплитуда случайной вариации

### 3.2 Изменить внешний вид эмоций (motik)

Файл: `scripts/emotions_display_node.py`

Функции рисования:
- `draw_happy()` — дуга-улыбка по центру (без глаз)
- `draw_sad()` — грустная дуга по центру (без глаз)
- `draw_neutral()` — горизонтальная полоса по центру (без глаз)
- `draw_cute()` — «милый» рот в форме W / uwu по центру
- `draw_smoke()` — сигарета с дымом (стилизация)

Чтобы добавить новую эмоцию:

```python
def draw_angry():
    img = Image.new("1", (W, H), 0)
    draw = ImageDraw.Draw(img)
    # ... ваш код рисования ...
    return img

# Добавить в словарь:
EMOTION_DRAWERS = {
    "neutral": draw_neutral,
    "happy": draw_happy,
    "sad": draw_sad,
    "angry": draw_angry,  # ← новая эмоция
}
```

После этого:
```bash
rostopic pub -1 /emotions std_msgs/String "data: 'angry'"
```

### 3.3 Добавить аудио файлы

Положите `.mp3` или `.wav` файлы в папку `voice/`:

```bash
cp мой_файл.mp3 /home/ubuntu/ros_ws/src/sound_mouth_motik_emotions/voice/
```

Воспроизведение:
```bash
rosservice call /oled_mouth/play_audio "data: 'мой_файл.mp3'"
```

### 3.4 Изменить частоту обновления дисплея

В `display_3d.launch`:
```xml
<arg name="mouth_sync_hz" default="30"/>
```

Увеличить для более плавной анимации (больше нагрузка на CPU), уменьшить для экономии ресурсов.

### 3.5 Изменить устройство вывода звука

```bash
# Узнать доступные устройства
aplay -l

# Запустить с конкретным устройством
roslaunch sound_mouth_motik_emotions display_3d.launch output_device:=plughw:2,0
```

## 4. Проверка работоспособности

```bash
# Проверить I2C
sudo i2cdetect -y 1
# Должны быть: 0x3C (инфо) и 0x3D (3D дисплей)

# Проверить ноды
rosnode list | grep -E "mouth|emotions"
# robot_mouth_talk_node
# emotions_display_node

# Проверить сервисы
rosservice list | grep oled_mouth
# /oled_mouth/play_audio

# Проверить топики
rostopic list | grep -E "oled_3d|emotions|audio"
# /oled_3d/active__driver
# /emotions
# /oled_mouth/audio_path
# /oled_mouth/mode
# /audio/mouth_open_level
# /audio/playback_level
```

## 4.1. Покой и старт осциллограммы (без скачка)

В **`robot_mouth_talk_node.py`**:
- Общие константы: **`MOUTH_CX`, `MOUTH_CY`, `MOUTH_BAR_W`, `MOUTH_BAR_H_IDLE`, `MOUTH_BAR_LEFT0`, `MOUTH_BAR_DX`, `MOUTH_BAR_H_MAX`** — одна геометрия для покоя, осциллографа и `draw_mouth_mode7`.
- **`MOUTH_BAR_H_MAX = 2 * min(MOUTH_CY, H - MOUTH_CY)`** (при кадре **128×64** и `cy=42` это **44** px): осциллограф **не выходит** за нижний край кадра. Раньше использовалось **46** px — низ **обрезался**, на OLED казалось, что рот «уехал вниз» и стал меньше.
- **`draw_idle_mouth()`** — три полоски **6×18** px, центр по вертикали **`MOUTH_CY` (42)**.
- **`draw_oscilloscope_frame`** — полоски расширяются **симметрично от `MOUTH_CY`**; в одном кадре у всех трёх **одинаковые** `h` и `top` (одна синус-модуляция на кадр). Раньше фазы различались по колонкам — полоски имели разную высоту и разный `top`, из‑за чего рот казался **смещённым и меньше** относительно покоя.
- В режиме **oscillogram** без данных `/audio/mouth_open_level` показывается **`draw_idle_mouth()`** (тот же вид, что после трека).
- При старте воспроизведения **`mouth_open = NORMAL_MOUTH_OPEN` (0.08)** — первый кадр совпадает с покоем.

Скрипты **`robot_mouth_talk.py`** и **`sound_and_mouth_talk.py`**:
- **`robot_mouth_talk.py`**: покой = `draw_mouth_mode7(NORMAL_MOUTH_OPEN)`; при `mouth_open=0` полоски тоже **6 px** — совпадает с нодой в покое.
- **`sound_and_mouth_talk.py`**: покой после имитации = `draw_mouth_frame(NORMAL_MOUTH_OPENNESS=0.08)` — геометрия как у ноды; от **`MIN_OPENNESS (0.02)`** кадр **отличается** (другая высота полосок), это отдельный режим.

## 5. Устранение проблем

| Проблема | Решение |
|----------|---------|
| Дисплей не отвечает | `sudo i2cdetect -y 1` — проверить 0x3D |
| Нет звука | `aplay -l` — проверить устройство; `amixer sget Master` — проверить громкость |
| Конфликт на 0x3D | Остановить `oled_display.service` если он пишет на 0x3D |
| Файл не найден | Положить в `voice/` или указать полный путь |
| Эмоции не меняются | Проверить `rostopic echo /oled_3d/active__driver` — должно быть `motik` |
